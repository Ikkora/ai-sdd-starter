# Política de seguridad

## Versiones soportadas

La versión 1.x actual recibe correcciones de seguridad.

## Reportar una vulnerabilidad

No comuniques vulnerabilidades sensibles mediante Issues públicos ni incluyas
secretos reales en ejemplos o pruebas de concepto.

Usa GitHub Private Vulnerability Reporting para este repositorio cuando esté
habilitado. Si no está disponible, utiliza un canal privado del maintainer sólo
si dicho canal ya está documentado públicamente. Actualmente esta política no
declara un canal privado alternativo; no publiques detalles sensibles en un
Issue como sustituto.

Incluye en el reporte, cuando sea posible:

- la versión afectada;
- una descripción del impacto y el alcance;
- los pasos mínimos para reproducir el problema;
- el entorno relevante;
- una prueba de concepto saneada, sin credenciales ni datos reales;
- mitigaciones conocidas o una corrección sugerida.

## Tiempos de respuesta

El objetivo es acusar recibo dentro de cinco días hábiles y compartir una
primera evaluación dentro de diez días hábiles. Estos plazos son objetivos de
servicio y no constituyen una garantía contractual.
